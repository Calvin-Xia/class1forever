# Repository Guidelines

## Project Overview
Static classmate-distribution map ("蹭饭地图"). The page shows public province/city aggregate counts; names and schools are returned per-region only after a passphrase-authenticated session, served by four `/api/*` routes backed by a `CLASS_MAP_DATA` KV namespace.

The merged migration (main baseline d488775) runs **Astro 6 SSR on a single Cloudflare Worker + Workers Assets**: `output: 'server'` in `astro.config.mjs`, `wrangler.jsonc` with `main: "@astrojs/cloudflare/entrypoints/server"` and `assets: { binding: "ASSETS", directory: "./dist" }`. The KV binding keeps the same name (`CLASS_MAP_DATA`) and the same `id` / `preview_id`. The existing Cloudflare Worker is the global service; EdgeOne production onboarding and DNS cutover remain a human gate — the deployment commands, the secrets to rebind, the KV checklist, the rollback steps and the manual-step list live in `docs/cutover-runbook.md` (node `l4_cutover`). Student data is never shipped as a static asset.

## Build, Test, and Development Commands
- `npm install`: install dependencies (Node >= 22.12 — astro 6's `engines`).
- `npm run build`: the single gate — `node build.js`, which runs the static safety assertions (incl. `wrangler types --check`), then `astro check`, then `astro build`, then the artifact scan; it emits `dist/` (Worker entry + `dist/client` assets). `--static-only` / `--artifacts-only` are the diagnostic switches.
- `npm run check:dual`: existing Cloudflare full gates followed by EdgeOne build/contracts/fixture runtime and data release negative tests; no deployment or student upload.
- `npm run astro:check`: Astro + TypeScript type check over `src/**` and the generated types.
- `npm run dev:local`: the full local path with **no Cloudflare credentials**. It derives a local Worker config from `dist/`, seeds `students:public:v1` / `students:raw:v1` into a local KV, then runs `wrangler dev` on http://127.0.0.1:8788 with the demo passphrase `demo`. Requires `npm run build` first. Flags: `--port <n>`, `--reset`, `--state-dir <dir>`, `--public-file <path>`, `--raw-file <path>` (or the `STUDENTS_PUBLIC_FILE` / `STUDENTS_RAW_FILE` env vars).
- `npm run seed:local`: write the local KV fixtures only (pair it with `npm run dev` / `npm run cf:dev`).
- `npm run seed:preview`: write the **demo** fixtures (`FIXTURE_STUDENTS` from `scripts/local-runtime.mjs`) to the **preview** KV namespace (`wrangler.jsonc`'s `preview_id`) with `--remote`; needs `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID`. Used by the PR-preview workflow; it never reads `js/data.js`, so the real roster cannot reach the preview. It writes remote KV only, so it needs no `dist/` build.
- `npm run preview:upload -- --alias pr-<n> [--tag pr-<n>]`: derive `.wrangler/preview/wrangler.json` from `dist/server/wrangler.json` (independent worker `class1forever-preview` + the preview KV id — **not** `--env preview`, which resolves to the production KV), write the demo secrets file for this run, then `wrangler versions upload --preview-alias` and print a final `PREVIEW_URL=<url>` line. It uploads a version only — no traffic change, no production deployment. Requires `npm run build` first.
- `npm run preview:write-config`: only derive `.wrangler/preview/wrangler.json` (manual dry-run / bootstrap).
- `npm run test:api`: the four-route API contract assertions (`tests/api-contract.test.mjs`, node:test) — starts its own local Worker, reads no `.dev.vars`, needs no credentials. Requires `npm run build` first.
- `npm run test:touch`: real-browser gesture-semantics regression (`tests/map-touch.test.mjs`, node:test + Playwright, 11 cases) — tap drills; long-press / right-click / Taiwan tap open the info sheet and it must stay open; 「地区一览」 keyboard parity; the visible loading state; touch-then-mouse device discrimination. Requires `npm run build` first and a one-time `npx playwright install --with-deps chromium`. This is the only automated cover for the "late synthesised click closes the sheet" class of bug.
- `npm run dev`: `astro dev` — Astro's dev server, simulated bindings, local KV; secrets come from `.dev.vars`. It renders the new site now that the root `index.html` is archived (`legacy/index.html`); the `/api/*` routes work but its simulated KV is empty, so use `dev:local` when you need data.
- `npm run cf:dev`: `wrangler dev` against the real Worker entry — because `wrangler.jsonc` sets `remote: true` on KV it reads the **remote** KV, so it needs `npx wrangler login` first; it is not the credential-free path.
- `npm run preview`: `npm run build && wrangler dev` — build, then serve the Worker locally.
- `npm run worker:dryrun`: `wrangler deploy --dry-run --outdir .wrangler-dryrun` — validates the Worker/Assets config without deploying.
- `npm run check:runtime`: headless local Worker — asserts the rendered page has no inline scripts, that the document and static-asset responses carry identical security headers, and that `/.dev.vars` / `/js/data.js` / `/js/vendor/echarts.min.js` are not requestable.
- `npm run cf:types` / `npm run cf:types:check`: regenerate / verify `worker-configuration.d.ts` after any `wrangler.jsonc` binding change (`npm run build` already runs the `--check`).
- `npm run data:upload -- --dry-run`: validate the data source can build both KV datasets.
- `npm run data:upload` / `npm run data:upload:preview`: upload to production / preview KV. Without `--release-id` they only write the fixed `students:raw:v1` / `students:public:v1`, which a deployment that has `DATA_RELEASE_ID` set never reads — production data updates must go through a release ID (`scripts/data-release.mjs` prepare/verify/verify-readback, or the upload script's `--release-id <id>`).
- `git log --oneline -n 10`: inspect recent commit style before committing.

Local environment notes:

- **Same-origin POST needs an `Origin` header.** Astro's `security.checkOrigin` (on by default) rejects a non-`GET`/`HEAD`/`OPTIONS` request whose `Content-Type` is absent or form-like unless `Origin === <request origin>`, with `403 Cross-site POST form submissions are forbidden`. Browsers send `Origin` on every POST, same-origin included, so page code needs nothing; `curl` / Node scripts must add `-H "Origin: http://127.0.0.1:8788"`. This is intentional CSRF protection, not a defect — see `docs/migration-parity.md` §1.2 and its §7 revision log.
- **Windows sandbox:** workerd must be able to write to a temp directory. If `npm run build` / `dev:local` / `test:api` report `CreateDirectory #5 拒绝访问` (or workerd fails to start), point `TEMP`/`TMP` at a directory inside the workspace, e.g. `TEMP="$PWD/.wrangler/probe-tmp" TMP="$PWD/.wrangler/probe-tmp" npm run test:api`. **Do not reuse an in-repo `TEMP` for `npm run check:dual`**: `tests/data-release.test.mjs` requires its private artifacts to live *outside* the repository, and `os.tmpdir()` follows `TEMP`, so an in-repo temp dir fails 3 cases with `PATH_MUST_BE_OUTSIDE_REPOSITORY` (point `TEMP`/`TMP` outside the repo for that command; `test:api` / `dev:local` are fine either way).
- **One writer per local KV:** the local KV is a miniflare SQLite directory. Concurrent runs need different `--state-dir` values (the API tests already isolate themselves in `.wrangler/local/state-test`).
- **`astro dev` binds IPv6 by default:** it listens on `[::1]`. In sandboxes that refuse IPv6 loopback (`connect EACCES ::1:<port>`) probe it with `npx astro dev --host 127.0.0.1 --port <n>`; `wrangler dev` (dev:local / cf:dev) already binds `127.0.0.1`.

## Coding Style & Naming Conventions
- Use UTF-8 for reads/writes; 4-space indentation in HTML/CSS/JS.
- JavaScript uses camelCase; keep functions focused.
- CSS follows existing component/modifier patterns such as `map-frame__corner--tl`.
- All page colours must resolve through `:root` custom properties. The only literal values allowed outside that block are the two `.auth-modal__feedback[data-variant=...]` colours — `scripts/check-contrast.js` reads them with a regex and cannot parse `var(...)` — and the `black` stop in the `.atmosphere__grid` mask, which is an alpha channel rather than a design colour.
- `--color-text-muted` must stay readable on **both** `--color-bg-primary` and the darker `--color-bg-secondary`: the map credit and the scale label sit on the inset colour, and at `#5f6a63` they were 4.48:1. Both pairs are asserted in `scripts/check-contrast.js` now, so shortening the token fails the build.
- `:root` declares `color-scheme: light`. Without it a system dark mode repaints native scrollbars and form controls dark and they fight the paper surfaces.
- Interactive elements get `touch-action: manipulation` from the generic `button, a, input` rule. Deliberately not applied to `#map`, which needs native pan and pinch.
- `.spotlight` must never declare `position`. It sits after `.share-btn` in the cascade, so `position: relative` there silently overrides that button's `position: absolute` and drops it into the document flow, pushing the map down by 40px. Elements that need positioning declare it themselves.
- Icons share one 24×24 grid and take size, stroke, caps and colour from the `.icon` / `.icon--xs|sm|md|lg` classes. `stroke-width` is computed per size so the **rendered** stroke is a constant 1.5px (one shared number would render 1.13px at 16px and 1.7px at 24px). Never put `stroke-*` presentation attributes on the paths inside an icon — they outrank that CSS — and never introduce a size outside the four tokens. Icons are always inline SVG: no emoji, no icon font, no text glyph standing in for an icon.
- Province map filenames stay lowercase pinyin (example: `zhejiang.js`).
- No linter/formatter; keep changes minimal and consistent with nearby code.

## Map Rendering Notes

The rules below are the **equivalence baseline carried over from the pre-migration site** (`js/map.js` and friends), **except where a deviation is explicitly recorded**. The recorded deviations are all part of the 2026-10-17 user-authorised product change: the gesture-driven click semantics (long-press/right-click open the sheet, late synthesised clicks never close it) and its follow-up fixes (a visible map loading state, and a device-aware touch-click guard) — these are deliberate product changes, not migration regressions; see `docs/parity-touch-compare.md`. They stay binding as the map moves into the `src/` islands: where a bullet names an old file path, read it as the behaviour contract, not as the current location. Those classic scripts and the stylesheet now live under `legacy/` (`legacy/js/{boot,geo,map,palette,motion,data.template}.js`, `legacy/css/main.css`); `js/china.js` and `js/province/**` deliberately stay at the repo root because the running site loads them.

- The geo files are pre-projected (EPSG:3415, metres), so `series.aspectScale` must stay `1`. ECharts' default `0.75` is meant for lng/lat data and squashes these maps by a third.
- ECharts only fills 80% of its layout box, so `BASE_ZOOM` is `1.25`; it doubles as the minimum zoom. Keep `scaleLimit.min` and the initial `zoom` in sync with it.
- Geometry stays as-is; do not hand-edit `js/china.js` or `js/province/*.js` (they stay at the repo root — the running `src/lib/geo-loader.ts` loads them). If a province map is added or removed, update `AVAILABLE_PROVINCE_FILES` in `src/lib/geo-loader.ts`, which is what the gate reads; `legacy/js/geo.js` keeps the pre-migration contract copy — `npm run build` fails on a mismatch.
- The China GeoJSON also carries `filename` for Taiwan/Hong Kong/Macau/Nanhai, but no province files exist for them; the whitelist is what prevents a doomed drilldown request.
- Colours live in two places on purpose (`src/styles/main.css` tokens for the page, `src/styles/palette.ts` for canvas drawing; `legacy/css/main.css` / `legacy/js/palette.js` are the retired comparison copies). Change both or `npm run build` fails. Text on the share image's header gradient is checked at the gradient midpoint. Solid button fills use white on `--color-accent-strong` (8.93:1); `--color-accent-primary` is the focus-ring / stat-number colour, and while white on it technically clears AA (4.62:1) it is not a button fill.
- The `visualMap` legend is sized and placed by `legendLayout()` in `js/map.js`: below 768px the ruler shortens and shifts right so the `0 人` tick clears the 44px zoom cluster in the bottom-left corner. It reads `window.innerWidth` when the option is built, so a live resize re-centres the legend but keeps its length until the next view change.
- Every way of opening a region goes through `activateRegion(point, source, intent)` in `src/lib/map-island.ts` (baseline: `js/map.js`). The map click handler, the right-click handler, `TapFallback` (touch tap / long-press) and the 「地区一览」 row buttons all call it, so the paths can never drift apart; add new entry points there, not by duplicating the drilldown/detail branches. `intent` is `'auto'` (tap / left-click: drill if drillable, otherwise open the sheet), `'panel'` (long-press, right-click, ledger 详情: force the sheet) or `'drill'` (forced drill for the sheet's drilldown button); it must never be gated on `detailMode.enabled` again. `source` distinguishes the input device: `'map'` for a mouse click on the chart, `'touch-tap'` / `'touch-hold'` for the touch fallback, `'right-click'`, and `'ledger'` / `'ledger-detail'` / `'sheet'` / `'probe'` / `'external'` for the other entry points. `map:region-activate` carries that `source`; `map:drill-start` is emitted in `drillIntoProvince()` only after the `point.loading` guard (and setting `point.loading = true`) and **before any `await`**, so the sheet closes immediately. Both chart event handlers (`handleRegionClick`, `handleRegionContextMenu`) **must return early when `ownsTouchGesture()` is true** — see the TapFallback bullet.
- 「地区一览」 (`.region-ledger`) is the keyboard and screen-reader substitute for the canvas chart: a native `<table>` inside `<details>` with **two buttons per region** (「查看」 = `data-action="view"` / `intent='auto'`; 「详情」 = `data-action="detail"` / `intent='panel'`) and `aria-sort` on the sorted column. Do not give `.region-table thead th` `position: sticky` — a sticky header plus the fixed bottom sheet can cover a focused row button (WCAG 2.2 2.4.11).
- Dialogs (bottom sheet, passphrase modal) go through `FocusScope` in `js/map.js`: background `inert`, focus moved inside, focus restored on close. `#map` and `#bottom-sheet` carry `tabindex="-1"` purely as focus anchors. The sheet is dismissed by sliding it off-screen with `bottom`, so `BottomSheet.updateButtons()` must also set `hidden` on `#bs-close` / `#bs-primary-btn` / `#bs-drilldown-btn` whenever the sheet is not `.active` — otherwise they stay focusable at y≈1660 and Tab lands on invisible controls. The map canvas itself is still not keyboard operable; `#region-table-body` is what makes region selection reachable without a pointer. The sheet's overlay `#bs-overlay` closes on `pointerdown`, **never `click`**: a touch's late synthesised click must not hit an overlay that has just appeared (that was the F-P1 defect; see `docs/parity-touch-compare.md`, 2026-10-17 ruling). `#auth-overlay` keeps `click` — it has no late-click problem.
- ECharts paints to canvas, so the `prefers-reduced-motion` block in the stylesheet (`legacy/css/main.css` in the pre-migration baseline, `src/styles/main.css` now) cannot reach it. `chartAnimationEnabled()` in `js/map.js` reads the media query separately and feeds `animation` / `animationDuration`; keep both halves in sync when touching motion.
- **Touch taps on the map do not rely on `chart.on('click')` alone.** zrender only synthesises a click when `touchend` lands within 300ms of `touchstart` (`zrender/lib/dom/HandlerProxy.js`, `TOUCH_CLICK_DELAY`), and its own click also has a 4px down/up movement threshold (`zrender/lib/Handler.js`), so a deliberate tap on a small province silently does nothing — while the DOM-based 「地区一览」 buttons keep working, which is exactly the "list works, map doesn't" bug. `TapFallback` (`src/lib/tap-fallback.ts`, migrated from `js/map.js:1606`) re-implements the gesture with `MAX_MOVE_PX = 14`, `HOLD_MIN_MS = 300`, `MAX_DURATION_MS = 2000`, `DEDUPE_MS = 450`; it resolves the region by converting the pixel through the public `convertFromPixel` API and ray-casting the current GeoJSON, and splits by hold duration: <300ms → `activateRegion(point, 'touch-tap', 'auto')`, 300–2000ms → `activateRegion(point, 'touch-hold', 'panel')` (a press longer than 2000ms is not a tap). Holding for 300ms sets `#map-press-ring` to `data-visible="true"` at the touch point (left/top relative to `.map-frame`'s padding box, with the 1px border correction); `touchend` / `touchcancel` / the 2000ms expiry set it back to `"false"`, and a missing element must be skipped silently. **`ownsTouchGesture()` is the dedupe owner for a touch gesture's late chart events**: it returns true while a one-finger gesture is in progress and for 450ms after it ends, and both `handleRegionClick` and `handleRegionContextMenu` must return early on it — otherwise one touch is recorded as both `'touch-tap'` and `'map'`, or a late canvas click (after a drill) activates a different region, or a long-press's synthesised `contextmenu` is recorded as `'right-click'`. The decision is by **input device**, not just by time: a capture-phase `pointerdown` listener on the same viewportRoot records `pointerType === 'mouse'` into `lastMousePointerDownAt`, and the guard yields when `lastMousePointerDownAt > lastTouchGestureAt` (a real mouse press inside the touch window); kernels that never send `pointerdown` leave it at 0, so the guard automatically falls back to the plain 450ms always-yield window (safe direction: swallowing one mouse click beats double-recording a touch). **The mouse-pass branch is unreachable on Chromium**, and that is not the guard's doing: zrender's `env.pointerEventsSupported` is only true for Edge/IE (`zrender/lib/core/env.js:69-71`), so Chrome/Firefox/Safari take the touch+mouse branch and `setTouchTimer()` holds `scope.touching` for **700ms** (`zrender/lib/dom/HandlerProxy.js:38-48`), during which the mouse listeners are skipped wholesale (`HandlerProxy.js:197-210`) — the mouse click never reaches ECharts at all. Measured boundary: Δ≈628ms and Δ≈668ms after a touch give zero `chart.on('click')`; Δ≈741ms and later recover (`tests/map-touch.test.mjs:889-896`). That ~700ms touch-then-mouse dead zone is **baseline behaviour of the same zrender 6.1.0 in the pre-migration site** (verified from `90c182b:js/vendor/echarts.min.js`), not something this change introduced; the device-based guard's gain therefore only lands on the pointer-events branch (Edge/IE). Known theoretical blind spot (reported by map-core, still open): a kernel that violates the spec and synthesises a **trusted** `pointerdown(pointerType='mouse')` for a touch would make the window pass the synthetic click through. Measured on Chromium (T19, reverse-patched dist), that failure mode is a **mislabelled single activation** — `'map'` instead of `'touch-tap'` — because the 450ms dedupe absorbs TapFallback's path and zrender's 700ms touch-mouse gate blocks the compat click, so nothing extra arrives. On a pointer-events kernel (Edge/IE) an additional path is conceivable but **unmeasured**: after a long press, TapFallback's own activation plus the gate-free compat click could yield two activations. It therefore stays recorded as an open blind spot, never as excluded; the safe direction is to yield, and no such kernel behaviour was observed on Android/iOS (`.wrangler/probe-tmp/pointer-probe.mjs`, scratch). **This blind spot remains, and `isTrusted` cannot help here**: a spec-violating kernel could fabricate a *trusted* mouse `pointerdown`, which is a different failure from the page-script case below. **Page-script forgery is closed (T17, user-authorised 2026-10-17):** `handlePointerDown` now only accepts `event && event.isTrusted && event.pointerType === 'mouse'` (`src/lib/tap-fallback.ts:347`), so a script-fabricated `dispatchEvent(new PointerEvent('pointerdown', { pointerType: 'mouse' }))` is untrusted, never stamps `lastMousePointerDownAt`, and zrender's synthesised click stays `'touch-tap'` with no second activation; kernels that do not expose `isTrusted` fail the condition → no stamp → the guard falls back to the safe 450ms always-yield window. Real input is unaffected: a real touch's derived click carries `pointerType='touch'` and has no preceding `pointerdown(mouse)`. Regression: the 11th `test:touch` case — remove the `isTrusted` check and it fails with source `'map'`. Unloading must reset the ownership window and the mouse-pointer timestamp to zero (not just `false`): otherwise a stale window leaks into the next chart instance, and on kernels without `pointerdown` its first 450ms of real mouse clicks would be yielded (safe direction, but not intended). `initTapFallback(chart, …)` **must be called after** the chart instance is stored (the baseline's `AppState.chart = chart`) — reading it before returns null and the listeners silently never bind.
- **Click semantics are gesture-driven, not detail-mode-gated.** In the national view: tap / left-click a drillable province → drill down; tap / left-click Taiwan / Hong Kong / Macau / Nanhai → info sheet; **long-press (≥300ms) → info sheet**; **right-click → info sheet** (suppress the browser context menu only when the event lands on a resolved region). In a province view: tap / long-press → info sheet. `#details-btn` no longer gates map clicks: its only jobs are choosing whether the sheet defaults to 「同学信息」 or the public card and owning 「退出查看」, and it now lives in the page header (`.plate__eyebrow` row) instead of the map frame. Touch devices drill down on tap, same as desktop: there is no `!isTouchDevice` branch left in `activateRegion()`. The old "mobile always opens the aggregate sheet first" rule made a province take two taps to enter and read as an unresponsive map. Province counts stay reachable through 「地区一览」, which lists every region with its public count and offers both 「查看」 and 「详情」.
- **The map loading state (`#map-loading`) must stay outside `#map`.** `echarts.init(#map)` constructs a zrender canvas painter whose constructor clears its container (`root.innerHTML = ''`, `zrender/lib/canvas/Painter.js:114`), so any static child of `#map` — the old loading layer included — is **deleted the moment the chart initialises**; `showProvinceLoading()` / `hideMapLoading()` then toggled a detached node, which is why the 「正在加载 …」 text and spinner were invisible before 2026-10-17. The fix keeps `#map-loading` as a **direct child of `.map-frame`** (sibling of `#map`, same `position:absolute; inset:0; z-index` geometry) and shows it with `display:flex` / 「正在加载 <省> 地图...」 during a drill, back to `display:none` when done (`src/lib/map-island.ts:125-148`; Markup in `MapSection.astro`). It carries `aria-hidden="true"` as a hard requirement: outside the `role="img"` container it would re-enter the accessibility tree and duplicate `#map[aria-busy]` and the footer `role="status"` announcement. `.map-loading` uses `background: var(--color-bg-primary-translucent)` (the same token as `.cdn-error`) because the text sits over the old choropleth and the heat scale has dark ends (`#35604d`); while visible it absorbs pointer events, which is the intended "map is busy" behaviour. Do not move it back inside `#map`, and do not describe the loading layer as invisible. **The pre-migration site had the same defect (its loading layer was also deleted by `echarts.init`), so making it visible is a recorded, user-authorised improvement, not a parity regression.** Covered by the loading-visibility case in `npm run test:touch`.
- **`favicon.svg` must not be a map drawing, and this is a data-integrity rule, not a taste call.** At 32px there is no room for the South China Sea inset that Chinese maps are expected to carry, and every attempt to simplify `js/china.js` into a silhouette drops those islands — an area threshold removes them as specks, and lowering the threshold just produces unreadable noise. A previous revision did exactly that and shipped an incomplete map as the site icon. The icon therefore uses cartographic vocabulary instead of geography: a seal-shaped square ring (echoing `.plate__seal`) around a compass rose, north point in seal red. If you want a map-like icon, it has to be an abstract cartographic mark — never a partial national outline.
- Share-image stats follow the current view: the national view prints the national `stats`, a province view prints that province's 人数 / 覆盖城市 / 占全班, and a province with no records prints one empty-state line instead of a row of zeros. Everything printed is read before the first `await`: `createSharePlan()` freezes the scope and date for both the subtitle and the filename, and `captureMapSnapshot()` returns the legend's `heatMax`, so an Esc pressed during the `Image` decode cannot leave the colours, the legend scale and the filename on three different scopes. Dates in the subtitle and filename use the browser's local time zone; `toISOString()` is UTC and writes the previous day for an early-morning export.
- The screen-reader note (`#interaction-note`) takes its numbers from the same `getProvinceSummary()` as the share image: a province view announces 「覆盖 N 座城市，共 M 位同学」 and a province with no records announces the empty state — the national totals must never be appended to a province name. Its details-mode hint follows the scope too, because the sheet's drilldown button does not exist in a province view.

## Security & Data Rules
- On this branch the runtime env is read with `import { env } from 'cloudflare:workers'` (`Astro.locals.runtime` is gone in Astro 6). `DETAILS_PASSPHRASE` / `DETAILS_SESSION_SECRET` come from that env and are never hardcoded; `worker-configuration.d.ts` is generated by `npm run cf:types` and must be regenerated after any `wrangler.jsonc` binding change.
- Never commit `.dev.vars`, `js/data.js`, or any full student list; never serve them as static assets.
- Passphrase and session secrets come from Cloudflare secrets (`DETAILS_PASSPHRASE`, `DETAILS_SESSION_SECRET`) or local `.dev.vars`; never hardcode them.
- Keep the page same-origin only: no CDN `<script>` tags and no inline `<script>` blocks, so `_headers` can keep `script-src 'self'`. `build.js` enforces both.
- **Read-only acceptance probes are a contract, not a public API.** The production page exposes `window.__mapProbe` (map state / points / hit-test) and `window.__dialogsProbe` (dialog state) for the external acceptance scripts. They are read-only and additive: page code must not depend on them, and they must not be removed or renamed without updating those scripts.

## Testing Guidelines
Automated coverage lives in `.github/workflows/ci.yml` (Node 24 — astro 6 requires `>= 22.12`). On push/PR it runs, in order: `npm ci` → `npm run build` (the single gate: static assertions + `wrangler types --check` + `astro check` + `astro build` + artifact scan) → `npm run check:runtime` (headless local Worker: no inline scripts, security headers identical between document and static assets, `/.dev.vars` / `js/data.js` / vendor path unreachable) → `npm run test:api` (four-route contract assertions, own local Worker + local KV + demo passphrase, no `.dev.vars`) → a separate `npx playwright install --with-deps chromium` step → `npm run test:touch` (real-Chromium gesture semantics: tap drills; long-press / right-click / Taiwan tap open the sheet and it must stay open; 「地区一览」 keyboard parity; one gesture = exactly one activation; loading-state visibility; touch-then-mouse device discrimination — 11 cases) → `npm run check:edgeone` → same-host session + GeoDNS negative controls → dual-deploy artifact/production-ordering assertions → a `node --check` loop over `js/`, `shared/`, `scripts/`, `tests/` and `build.js` (the `functions/` pass already skips a missing directory, since the routes are archived in `legacy/functions/`). `npm run check` locally is still only `build + check:runtime + test:api`; touch tests are a separate command because the Playwright browser binary is not part of `npm ci`. The legacy vendor-sync step is **gone** (ADR-0002 retired the artifact); the full gate breakdown is in `docs/build-gates.md`.

PR previews are a **separate, non-gating** path: `.github/workflows/preview.yml` runs only on same-repo PRs and always uses a dedicated worker (`class1forever-preview`) + the preview KV namespace + the `FIXTURE_STUDENTS` demo data (`npm run seed:preview` / `preview:upload -- --alias pr-<n>`) — never a shared production state, never `--env preview` (the redirected `dist/server/wrangler.json` has no `env.preview` block, so it resolves to the production KV). A preview failure or absence must not block a merge; production still publishes only through `deploy.yml`'s manual gate. See `docs/ci-deployment.md`.

`build.js` checks the required files of the **new** tree (`tests/map-touch.test.mjs` is in the required-files array), that the root `index.html` stays archived (dev shading), that the detail-data key / `js/data.js` / the `DETAILS_*` names never reach the client surface or `dist/client`, that no script is cross-origin or inline (no `<script is:inline>` without `src`), that no Highcharts reference and no vendor-bundle load remain, that the province whitelist matches `js/province/`, that the two `script-src` declarations carry no `unsafe-inline`, that `public/_headers` and `src/lib/security-headers.ts` stay in lockstep, that the Node engines ranges still satisfy `astro` / `wrangler` / `@astrojs/react`, and (via `scripts/check-contrast.js`) that key text/background pairs meet WCAG AA and that the `src/styles/main.css` tokens match `src/styles/palette.ts`. Its success message (static assertion count, `astro check` + `astro build` exit codes, artifact scan) describes the **Worker + Workers Assets** deployment, not Pages.
